# Guide — sauvegarder vers un bucket S3

Akooti écrit un fichier `.akooti` (les deux fichiers du coffre, déjà chiffrés)
dans un bucket compatible S3. Le pilote signe les requêtes en **SigV4
path-style** : AWS, Cloudflare R2, MinIO et Wasabi fonctionnent avec la même
configuration.

## 1. Créer le bucket et une clé

### AWS S3

1. Console AWS → **S3** → **Create bucket** (région `eu-west-3` par exemple,
   accès public bloqué).
2. **IAM** → **Users** → *Create user* sans accès console.
3. *Attach policies directly* → politique minimale :

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject", "s3:ListBucket", "s3:DeleteObject"],
      "Resource": [
        "arn:aws:s3:::MON-BUCKET",
        "arn:aws:s3:::MON-BUCKET/akooti/*"
      ]
    }
  ]
}
```

4. **Security credentials** → *Create access key* → noter la clé d'accès et la
   clé secrète (affichée une fois).

### Cloudflare R2

1. R2 → **Create bucket**.
2. **Manage R2 API Tokens** → *Create API token* avec *Object Read & Write* sur
   ce bucket → noter `Access Key ID` / `Secret Access Key`.
3. Endpoint : `https://<compte>.r2.cloudflarestorage.com`, région `auto`.

### MinIO / Wasabi

- MinIO : créer le bucket et un utilisateur avec les mêmes droits ; endpoint
  `https://minio.exemple.test:9000`.
- Wasabi : endpoint par région, par exemple
  `https://s3.eu-central-1.wasabisys.com`.

## 2. Remplir Akooti

**Sync & sauvegardes** → **Cibles de sauvegarde** :

| Champ | Valeur |
| ----- | ------ |
| Fournisseur | `S3 compatible` |
| Endpoint | `https://s3.eu-west-3.amazonaws.com` (sans slash final) |
| Région | `eu-west-3` (R2 : `auto`) |
| Bucket | nom exact du bucket |
| Préfixe | `akooti` (facultatif, évite de mélanger avec d'autres objets) |
| Clé d'accès / clé secrète | celles de l'étape 1 |
| Intervalle | 60 minimum |
| Instantanés conservés | 2 à 24 selon votre usage |

Cliquer **Tester** : « Bucket accessible » signifie que la signature et les
droits sont bons. Validé sur un MinIO local (`http://127.0.0.1:9000`,
path-style, région `us-east-1`, bucket existant) : test, envoi, rétention et
téléchargement de l'objet (magic `AKOOTI-SNAP1`). Puis **Ajouter la cible**.

> Les identifiants sont chiffrés dans la base locale ; ils ne sont jamais
> renvoyés à l'interface. En modification, laisser les champs secrets vides
> conserve ceux déjà enregistrés.

## 3. Vérifier

```bash
aws --endpoint-url https://s3.eu-west-3.amazonaws.com \
    s3 ls s3://MON-BUCKET/akooti/
```

Après un **Sauvegarder** (ou le tick de 60 s), un objet
`akooti-<epoch-ms>.akooti` apparaît. La rétention supprime les plus anciens
au-delà du nombre conservé.

## 4. Dépannage

| Symptôme | Cause | Correction |
| -------- | ----- | ---------- |
| `S3 a refusé la requête (403)` | clé/secret erronés, région différente de celle du bucket, droits manquants | vérifier la politique IAM et la région |
| `S3 a refusé la requête (400)` | endpoint avec chemin ou bucket dans l'URL | endpoint racine uniquement, chemin géré par Akooti |
| `S3 injoignable` | URL, proxy ou TLS | tester `curl -I <endpoint>` |
| `SignatureDoesNotMatch` (AWS) | horloge système décalée | synchroniser l'heure |

## 5. Bonnes pratiques

- Un bucket dédié (ou un préfixe dédié) par appareil, pour que la rétention ne
  supprime pas les instantanés d'un autre appareil.
- Activer le versioning ou une règle de cycle de vie côté bucket : Akooti gère
  sa propre rétention, le bucket peut garder une marge.
- Tester une **restauration** au moins une fois : verrouiller le coffre →
  écran de déverrouillage → *Restaurer un instantané*.
